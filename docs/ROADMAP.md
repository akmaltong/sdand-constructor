# ROADMAP

Два этапа поставки согласно ТЗ (фото 3).

---

## Этап 1 — MVP «мини-конструктор»

**Цель:** доказать ключевую механику — метровая привязка, размещение моделей с коллизиями, экспорт сцены.

**Срок ориентировочно:** 4–6 недель (1 разработчик + 1 моделлер).

### Задачи

- [ ] Форк / базовая настройка на основе `editor-0.9.1` (Pascal Editor)
- [ ] Ребрендинг и переименование пакетов (`@sdand/*`)
- [ ] Пресет одной площадки (например, XPO Forum) — статический 3D-зал
- [ ] Импорт 2D-подложки плана зала (PNG/PDF) как `Guide`
- [ ] Калибровка «метр → пиксель» на подложке
- [ ] Инструмент «стены» (уже есть в Pascal) — адаптировать под выставочные перегородки
- [ ] Инструмент «зоны» (уже есть) — под площади стендов
- [ ] Метровая сетка на полу + snapping шагом 0.5 м / 1 м (`snapping` пакет)
- [ ] Библиотека 5–10 тестовых моделей стендов (`gltf`)
- [ ] Drag-n-drop моделей в сцену
- [ ] Поворот моделей шагом 45°
- [ ] Коллизии — запрет размещения на занятой площади (использовать `spatialGridManager.canPlaceOnFloor`)
- [ ] Сохранение/загрузка сцены в JSON (локально + IndexedDB)
- [ ] Экспорт сцены в `gltf`
- [ ] Демо-сборка на Vercel

### Definition of Done Этапа 1
- Один пользователь может открыть план зала, нарисовать зоны, поставить 3–5 стендов из библиотеки, сохранить и открыть заново.
- Коллизии работают — модель не встаёт на занятое место.

---

## Этап 2 — «Полноценный функциональный проект»

**Цель:** мультипользовательская платформа с аккаунтами, синхронизацией, AI и биллингом.

**Срок ориентировочно:** 4–6 месяцев (команда из ~4 человек, см. [ESTIMATE.md](ESTIMATE.md)).

### 2.1 Мультиплощадки
- [ ] Пресеты нескольких залов (XPO Forum, Гостиный двор, …)
- [ ] Админ-интерфейс для загрузки новых площадок

### 2.2 Аккаунты и права
- [ ] Регистрация/авторизация (email, OAuth)
- [ ] Роли: организатор площадки, застройщик, заказчик стенда, модератор
- [ ] Приглашения в проект

### 2.3 Realtime-синхронизация
- [ ] WebSocket-сервер (или Yjs / Liveblocks)
- [ ] Каждый заказчик видит свой стенд + общий план зала
- [ ] Конфликты и блокировки при одновременном редактировании

### 2.4 Библиотека моделей и загрузка
- [ ] Загрузка `gltf` / `obj` пользователем
- [ ] Наложение картинки/текстуры (брендинг)
- [ ] Очередь модерации моделей
- [ ] Версионирование моделей

### 2.5 Нейронка «правит pivot/масштаб»
- [ ] Пайплайн обработки загруженной модели:
  - авто-центрирование pivot по нижней грани
  - нормализация масштаба по реальным метрам
  - генерация превью
- [ ] Автоматическая заливка в библиотеку после проверки

### 2.6 AI-генератор стендов
- [ ] Форма параметров (размер, отрасль, бюджет, стиль)
- [ ] LLM-обёртка (Anthropic / OpenAI) + шаблоны стендов
- [ ] Превью нескольких вариантов, выбор одного

### 2.7 Работа с 2D↔3D
- [ ] Импорт 2D-плана и авто-генерация 3D-сцены
- [ ] Обратный экспорт: 3D → плоский план (top-down)

### 2.8 Прайсинг и биллинг
- [ ] Тариф «весь продукт» (фикс)
- [ ] Тариф «час работы» (тайминг активной сессии)
- [ ] Интеграция платёжного шлюза (ЮKassa / Stripe)

### 2.9 Экспорт
- [ ] Экспорт зала в PDF (сверху + перспектива)
- [ ] Экспорт сцены в `gltf`
- [ ] Спецификация стендов (список с площадями, заказчиками)

### 2.10 Админка организатора
- [ ] Дашборд занятых/свободных площадей
- [ ] Заявки на площадки
- [ ] Статусы стендов (черновик / утверждён / оплачен / смонтирован)

### Definition of Done Этапа 2
- Организатор запускает выставку в системе, приглашает N заказчиков.
- Заказчики параллельно проектируют стенды, видят чужие в общем плане, не могут поставить свой на занятую площадь.
- Модели грузятся, автоматически обрабатываются, попадают в библиотеку.
- Организатор экспортирует итоговый план и спецификацию, заказчики оплачивают участие.
